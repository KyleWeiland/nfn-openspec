# Article Pipeline Scripts

This directory contains the Python scripts for the NoFrills.news article fetching and processing pipeline.

## Installation

Install the required dependencies:

```bash
pip install -r requirements.txt
```

Newspaper4k requires the NLTK `punkt_tab` tokenizer for NLP summarization. The pipeline downloads it automatically on first run (silently, no action needed).

## Dependencies

Dependencies are split across two files:

- `requirements.in` lists the direct dependencies, each pinned to an exact version.
  **Edit this file** to add, remove or bump a dependency.
- `requirements.txt` is generated by `pip-compile`. It pins the exact version of every
  package, including transitive ones. CI and local setup install from it. Don't edit
  it by hand.

Because everything is pinned, an upstream release can't change what CI installs.
Versions change only when a lock-file change is merged.

### Regenerating the lock file

After editing `requirements.in`, recompile with Python 3.11 on Linux to match CI. From
the repository root, with Docker:

```bash
docker run --rm -v "$PWD/scripts":/w -w /w python:3.11 sh -c \
  "pip install -q pip-tools && pip-compile --strip-extras --no-emit-index-url --output-file=requirements.txt requirements.in"
```

(On Git Bash for Windows, prefix the command with `MSYS_NO_PATHCONV=1` and use
`"$(pwd -W)/scripts"`.) Commit both files together.

To bump a single package without re-resolving everything, add
`--upgrade-package <name>` to the `pip-compile` command.

The lock leaves out hashes on purpose. It is compiled on Linux, so Windows-only
transitive dependencies (such as `colorama`) aren't pinned, and pip resolves them
itself during a local install on Windows.

### Upgrades

Dependabot (`.github/dependabot.yml`) opens one grouped pull request a week that
bumps the pins in `requirements.in` and recompiles `requirements.txt`, plus separate
PRs for security fixes. It does the same for the site's npm packages, which are also
pinned exactly (`site/.npmrc` sets `save-exact`, so `npm install <pkg>` stays exact).
On each PR that touches `scripts/` or `site/`, the **Dependency check** workflow
installs the Python lock and imports every pipeline module, runs `smoke_test.py`
(below), and builds the site with `npm ci` and `npm run build`. A green check means
the upgrade loads, summarizes and builds, not that its behavior is unchanged in
every case, so skim the changelogs of any major or 0.x bumps before merging.

### Smoke test

`smoke_test.py` exercises the runtime paths that an import cannot: it downloads the
NLTK `punkt_tab` tokenizer, extracts and summarizes `fixtures/smoke_article.html`
offline, then runs one gnews search, decodes one Google News URL and extracts one
real article. Run it from `scripts/` after any dependency change:

```bash
python smoke_test.py            # all checks
python smoke_test.py --offline  # tokenizer and summarizer only, no network
```

The network checks depend on Google News being reachable, so a failure there is
worth one re-run before blaming the upgrade.

### Comparing two site builds

`compare_dist.py` is the regression check for anything that changes the renderer
(an Astro upgrade, a template edit). It compares two `site/dist/` folders, or
builds two git refs in temporary worktrees first:

```bash
python scripts/compare_dist.py site/dist-before site/dist-after
python scripts/compare_dist.py --build main HEAD            # ~2 min per ref
python scripts/compare_dist.py --build main HEAD --sample 2000 --strict
```

It reports, in order: pages present in only one build; asset sizes (hashes
normalised) with totals per extension; visible-text differences; markup
differences grouped by cause, so a template change across 18,000 article pages
shows as one group with a sample diff; and the set of distinct inline scripts and
styles. Hashed asset names, Astro's scoped-style hashes and relative timestamps
("3h ago") are normalised before comparing.

Exit status is 1 when page paths or visible text differ. Markup, asset and
inline-code differences are reported but only fail with `--strict`. For an Astro
major, the expectation is: identical paths, identical text, and every markup group
explained by the changelog.

## Usage

### Run the Pipeline

To fetch and process articles from all configured feeds:

```bash
python fetch_articles.py
```

The script will:
1. Load feed queries and settings from `feeds.config.json`
2. Fetch articles via gnews for each configured query
3. Download and extract article content using Newspaper4k
4. Generate NLP summaries
5. Store articles in `data/articles.db` with deduplication

### Test the Modules

To run basic unit tests on the pipeline modules:

```bash
python test_modules.py
```

This tests:
- Slug generation
- Title normalization

## Configuration

Edit `feeds.config.json` in the repository root to add or remove feeds:

```json
{
  "gnews_settings": {
    "language": "en",
    "country": "US",
    "max_results": 10,
    "period": "1d"
  },
  "excluded_domains": ["youtube.com", "reddit.com"],
  "feeds": [
    {
      "query": "Technology",
      "category": "Technology"
    }
  ]
}
```

- `gnews_settings.period` — how far back to look (`"1d"`, `"7d"`, etc.)
- `gnews_settings.max_results` — max articles returned per query
- `excluded_domains` — domains to exclude from all queries
- `feeds[].query` — search term passed to Google News
- `feeds[].category` — category label stored with each article

## Module Overview

- `fetch_articles.py` - Main pipeline script
- `config.py` - Configuration file loading and validation
- `article_fetching.py` - gnews-based article discovery
- `article_processing.py` - Article download, extraction, and NLP summarization (Newspaper4k)
- `url_extraction.py` - URL utilities
- `database.py` - SQLite database operations
- `test_modules.py` - Unit tests for core functions

## Database Schema

Articles are stored in `data/articles.db` with the following schema:

```sql
CREATE TABLE articles (
    id INTEGER PRIMARY KEY,
    title TEXT NOT NULL,
    source_url TEXT NOT NULL,
    summary TEXT,
    category TEXT NOT NULL,
    published_date TEXT,
    slug TEXT NOT NULL,
    created_at TEXT NOT NULL,
    extraction_method TEXT
);
```

`extraction_method` records which pipeline produced the row. Articles fetched
before the gnews/Newspaper4k migration are marked `trafilatura`; everything
written since is marked `newspaper4k`. `init_database()` adds the column and
backfills unmarked rows automatically, so an older database upgrades in place
on the next run.

## Error Handling

The pipeline is designed to be resilient:
- Individual article failures don't stop the entire pipeline
- Network errors are logged and the pipeline continues
- Duplicates are automatically skipped
- Missing or malformed config causes immediate exit
- Zero results for a query logs a warning and continues

## Logging

All operations are logged to stdout with timestamps:
- INFO: Successful operations
- WARNING: Skipped entries or non-fatal failures
- ERROR: Fatal failures

Check the logs to debug issues or monitor progress.
